\section{Sequential behavior and correctness}
% ============================================================

\subsection{Sequential Jacobi and Gauss--Seidel}

Jacobi reads each iteration from one matrix and writes the new interior
values to a separate matrix, so every update uses the previous iteration's
neighbour values. The boundary cells are not updated. Gauss--Seidel
updates the matrix in place in row-major order; later cells in the sweep
can therefore observe values written earlier in that same iteration.
The driver stops when the residual is below the requested threshold or
when the maximum iteration count is reached.

The assignment validates each parallel solver against the sequential
output from the same solver, comparing the PPM and iteration count.

\section{Dependency analysis with Tareador}
% ============================================================

\subsection{Methodology and task decompositions}

Before implementing the parallel OpenMP solvers, we used Tareador to
analyze the intrinsic task-level parallelism and explore data dependencies
for both the Jacobi and Gauss--Seidel algorithms.
Tareador monitors memory references across programmer-specified task
boundaries demarcated by \texttt{tareador\_start\_task} and
\texttt{tareador\_end\_task}, generating a Task Dependency Graph (TDG).

For both solvers, we examined two distinct task decomposition models:
\begin{enumerate}[label=(\roman*)]
  \item \textbf{Coarse-grained (macro-task) baseline} (denoted by suffix
  \texttt{\_vanilla} in the retained \texttt{tdg/} artifacts): Tasks are
  instantiated at the outer function-call level in \texttt{heat-tareador.c},
  treating the entire solver sweep (\texttt{jacobi} or \texttt{gausseidel})
  and the matrix update (\texttt{copy\_mat}) as monolithic individual tasks.
  \item \textbf{Fine-grained 2D block-level decomposition} (denoted by suffix
  \texttt{\_modified} in \texttt{tdg/}): Tasks are placed inside the 2D
  spatial block loops of \texttt{solver-tareador.c}, subdividing the grid into
  an $n_{\mathrm{blocks},i} \times n_{\mathrm{blocks},j}$ grid of tiles
  (\texttt{solve(i,j)} and \texttt{copy(i,j)}).
\end{enumerate}

\paragraph{Handling the residual reduction.}
The iterative solver evaluates convergence by accumulating a scalar residual
\texttt{sum}. Because every thread writes into this shared accumulator,
it would introduce an artificial loop-carried dependency that serializes the
Tareador execution graph. Following the laboratory guidance, we enclosed
the reduction loop with \texttt{tareador\_disable\_object(\&sum)} and
\texttt{tareador\_enable\_object(\&sum)} to temporarily disable tracking on
\texttt{sum}, thereby uncovering the true spatial data dependencies of the
grid. In the OpenMP parallel implementations, this dependency is handled
safely with \texttt{reduction(+:sum)}.

\subsection{Jacobi solver analysis}

In the Jacobi formulation, computing cell $(i, j)$ at iteration $k$ reads
values exclusively from iteration $k-1$ in the input matrix $u$ and writes
the updated value to the separate output matrix $u_{\mathrm{help}}$ (or
$u_{\mathrm{new}}$). The Tareador analysis reveals two primary characteristics:

\begin{itemize}
  \item \textbf{Complete intra-iteration independence:} As shown in the
  fine-grained 2D-blocked TDG (Figure~\ref{fig:tdg-jacobi-fine}), all $4 \times 4 = 16$
  tile tasks within a single solver sweep are completely independent and can
  execute in parallel. The same embarrassingly parallel structure is observed
  for the subsequent 16 block-level matrix copy tasks.
  \item \textbf{Inter-iteration serialization:} The coarse-grained baseline
  (Figure~\ref{fig:tdg-jacobi-coarse}) illustrates the global synchronization
  boundary: the solver phase must terminate entirely before the matrix copy
  starts, and the copy phase must complete before the next iteration begins.
\end{itemize}

This structure confirms that Jacobi is well suited for geometric data
decomposition by rows or blocks with implicit OpenMP tasks. Moreover, the
explicit serialization of the copy phase in the TDG highlights an immediate
optimization opportunity: alternating matrix pointers between iterations
avoids copying memory altogether, eliminating the \texttt{copy\_mat} barrier.

\subsection{Gauss--Seidel solver analysis}

Unlike Jacobi, Gauss--Seidel updates the domain in place on the same
matrix $u$. Consequently, updating cell $(i, j)$ immediately consumes the
newly written values from its upper neighbor $(i-1, j)$ and left neighbor
$(i, j-1)$ within the current iteration:

\begin{itemize}
  \item \textbf{Coarse-grained baseline:} In the coarse baseline
  (Figure~\ref{fig:tdg-gauss-coarse}), with internal task directives omitted,
  the computation appears as a single monolithic block with no exposed task
  parallelism (\texttt{children\_pot\_tasks = 0}).
  \item \textbf{Fine-grained block-level decomposition:} When instrumented at the
  tile level ($4 \times 4$ blocks), Tareador maps the read-after-write
  dependencies between adjacent blocks. Each tile $(i, j)$ depends on the
  completion of tile $(i-1, j)$ directly above it and tile $(i, j-1)$ to its
  left. As visualized in the resulting TDG (Figure~\ref{fig:tdg-gauss-fine}),
  these constraints produce an \emph{anti-diagonal wavefront} pattern.
\end{itemize}

Execution progresses diagonally: concurrency begins with a single tile at
$(0,0)$, expands along subsequent anti-diagonals $(i+j=c)$ where all tiles are
independent and can run concurrently, peaks along the main anti-diagonal, and
contracts toward the bottom-right corner $(n_{\mathrm{blocks},i}-1, n_{\mathrm{blocks},j}-1)$.

This dependency structure demonstrates that parallelizing Gauss--Seidel
requires coordinating tile execution across iterations and wavefronts. This
finding directly informs our two OpenMP approaches: (1) dynamic task
scheduling using explicit tasks with dependency clauses (\texttt{\#pragma omp task
depend(in: ...) depend(out: ...)}), and (2) pipelined loop-level data
decomposition using \texttt{\#pragma omp ordered depend(sink: ...) depend(source)}.

\section{Parallel Jacobi}
% ============================================================

\subsection{Initial data decomposition}

The \texttt{lowerb}, \texttt{upperb}, and \texttt{numElem} macros divide
the \texttt{sizex-2} interior rows among the threads, distributing any
remainder over the first blocks and offsetting the row indices by one.
Thus, the fixed boundary rows are excluded and each thread scans all
interior columns. The arrays are shared, but each thread writes a
disjoint set of \texttt{unew} cells. The scalar temporaries are private,
and \texttt{sum} is combined with an OpenMP reduction.

\begin{lstlisting}[caption={Initial parallel Jacobi implementation.}]
 #pragma omp parallel private(tmp, diff) reduction(+:sum) 
        {

                int blocki=omp_get_thread_num();
                int nblocksi=omp_get_num_threads();
        
                int interior_rows = sizex - 2;
                int i_start = lowerb(blocki, nblocksi, interior_rows) + 1;
                int i_end = upperb(blocki, nblocksi, interior_rows) + 1;

                for (int i = i_start; i <= i_end; i++){
                        for (int j = 1; j<sizey-1; j++){
                                tmp = 0.25 * ( u[ i*sizey          + (j-1) ] +  // left
                                    u[ i*sizey     + (j+1) ] +  // right
                                    u[ (i-1)*sizey + j     ] +  // top
                                    u[ (i+1)*sizey + j     ] ); // bottom
                                diff = tmp - u[i*sizey+ j];
                                sum += diff * diff;
                                unew[i*sizey+j] = tmp;
          
        
                        }
                }       
                
                
        }       
\end{lstlisting}

\subsection{Detailed analysis of the initial version}

The model reports 1000 implicit tasks per worker with high strategy efficiency
(98\%), yet the overall parallel fraction is constrained to 73.83\%.
As identified in our earlier Tareador dependency analysis, every Jacobi
iteration requires a full matrix copy (\texttt{copy\_mat}) to transfer
$u_{\mathrm{help}}$ back to $u$. In this initial OpenMP implementation,
while \texttt{solve} is parallelized across threads, \texttt{copy\_mat}
remains sequential on the master thread between iterations. Because this
unparallelized memory copy scales with the entire grid ($1022 \times 1022$)
and executes sequentially at each step, it constitutes a substantial serial
bottleneck under Amdahl's law, directly explaining the low parallel fraction.

\subsection{Optimization}

\begin{lstlisting}[caption={Parallel interior-copy routine retained in the v1 source.}]
void copy_mat (double *u, double *v, unsigned sizex, unsigned sizey) {

    #pragma omp parallel
{

    int n_blocks = omp_get_num_threads();
    int blocki = omp_get_thread_num();

    int start_i = lowerb(blocki, n_blocks, sizex);
    int end_i = upperb(blocki, n_blocks,sizex); 

    for (int i = max(1, start_i); i <= min(sizex - 2, end_i) ; i++) {
        for (int j = 1; j < sizey - 1; j++) {
            v[i * sizey + j] = u[i * sizey + j];
        }
    }

}
}

\end{lstlisting}

\subsection{Further optimization, if implemented}

The v3 source implements the pointer-alternation optimization: after a
Jacobi step, it swaps \texttt{param.u} and \texttt{param.uhelp} rather
than copying every interior element. The two buffers alternate roles;
the solver writes only interior cells, leaving each buffer's boundary
cells unchanged. The driver writes the buffer currently referenced by
\texttt{param.u} after the final iteration.

case 0: // JACOBI
    residual = solve(param.u, param.uhelp, np, np);
    double *aux = param.u;
    param.u = param.uhelp;
    param.uhelp = aux;
    break;
\end{lstlisting}

for v2, a 1.18x elapsed-time improvement (15\% lower).

\section{Parallel Gauss--Seidel}
% ============================================================

\subsection{Blocking and dependency structure}

The Gauss--Seidel solver partitions the matrix into
\texttt{nblocksi} row blocks and \texttt{nblocksj} column blocks and
visits tiles in increasing row-block, then column-block, order.
The \texttt{lowerb}/\texttt{upperb} macros balance non-divisible
dimensions; each tile clips its iteration to the interior range
\texttt{1..sizex-2} by \texttt{1..sizey-2}. Since updates are in place,
each tile must wait for its left and upper neighbours. The resulting
anti-diagonal wavefront permits concurrent tiles without violating the
Gauss--Seidel read-after-write order.

\subsection{Task decomposition with explicit dependencies}

The explicit-task version creates one task per tile inside a
\texttt{single}/\texttt{taskgroup}. Each task owns a tile, keeps
\texttt{tmp} and \texttt{diff} private, and participates in the
taskgroup reduction for the residual. The two \texttt{depend(in:)}
locators represent the left and upper predecessor tiles; the
\texttt{depend(out:)} locator identifies the tile's bottom-right cell
for successor matching. The taskgroup completes all tile work and
combines the residual before the next solver iteration begins.

\begin{lstlisting}[caption={Explicit Gauss--Seidel tile tasks (v1).}]
int nblocksi = omp_get_max_threads();
int nblocksj = nblocksi;

#pragma omp parallel
{
  #pragma omp single
  {
    #pragma omp taskgroup task_reduction(+:sum)
    {
      for (int blocki = 0; blocki < nblocksi; ++blocki) {
        int i_start = lowerb(blocki, nblocksi, sizex);
        int i_end = upperb(blocki, nblocksi, sizex);
        for (int blockj = 0; blockj < nblocksj; ++blockj) {
          int j_start = lowerb(blockj, nblocksj, sizey);
          int j_end = upperb(blockj, nblocksj, sizey);
          #pragma omp task in_reduction(+:sum) private(tmp,diff) \
            depend(in: u[i_end*sizey+j_start-1], \
                       u[(i_start-1)*sizey+j_end]) \
            depend(out: u[i_end*sizey+j_end])
          {
            for (int i = max(1,i_start); i <= min(sizex-2,i_end); ++i)
              for (int j = max(1,j_start); j <= min(sizey-2,j_end); ++j) {
                tmp = 0.25 * (u[i*sizey+j-1] + u[i*sizey+j+1]
                              + u[(i-1)*sizey+j] + u[(i+1)*sizey+j]);
                diff = tmp - u[i*sizey+j];
                sum += diff * diff;
                u[i*sizey+j] = tmp;
              }
          }
        }
      }
    }
  }
}
\end{lstlisting}

The left locator matches the preceding tile's last-column output, and
the upper locator matches the preceding row tile's last-row output.
The output locator permits the next tile to depend on this tile.

\subsection{Data decomposition with do-across}

The do-across version distributes row-block iterations among the
implicit tasks and iterates over column blocks inside each row block.
The ordered source/sink clauses express the same left and upper
predecessor relations as the task version. Its reduction combines the
per-cell residual contributions.

\begin{lstlisting}[caption={Gauss--Seidel do-across dependency loop (v2).}]
int nblocksi = omp_get_max_threads();
int nblocksj = nblocksi;

#pragma omp parallel for ordered(2) private(tmp,diff) reduction(+:sum)
for (int blocki = 0; blocki < nblocksi; ++blocki) {
  int i_start = lowerb(blocki, nblocksi, sizex);
  int i_end = upperb(blocki, nblocksi, sizex);
  for (int blockj = 0; blockj < nblocksj; ++blockj) {
    int j_start = lowerb(blockj, nblocksj, sizey);
    int j_end = upperb(blockj, nblocksj, sizey);
    #pragma omp ordered depend(sink: blocki, blockj-1) \
                         depend(sink: blocki-1, blockj)
    for (int i = max(1,i_start); i <= min(sizex-2,i_end); ++i)
      for (int j = max(1,j_start); j <= min(sizey-2,j_end); ++j) {
        tmp = 0.25 * (u[i*sizey+j-1] + u[i*sizey+j+1]
                      + u[(i-1)*sizey+j] + u[(i+1)*sizey+j]);
        diff = tmp - u[i*sizey+j];
        sum += diff * diff;
        u[i*sizey+j] = tmp;
      }
    #pragma omp ordered depend(source)
  }
}
\end{lstlisting}

Each tile waits for its left and upper tile before updating in place,
then publishes completion as a source for its right and lower
successors.

\subsection{Configurable number of column blocks}

The assignment specifies
\[
  n_{\mathrm{blocks},j}
  = n_{\mathrm{blocks},i}\times \texttt{userparam}.
\]

\texttt{-u} sets the global \texttt{userparam}, which
the solver multiplies by the row-block count to obtain the number of
column blocks. The lower/upper-bound macros distribute remainder
elements across early blocks, while the tile loops clip their work to
interior cells.

\begin{lstlisting}[caption={Column-block count in the v3 solver.}]
int nblocksi = omp_get_max_threads();
int nblocksj = nblocksi * userparam;
\end{lstlisting}

Increasing \texttt{userparam} creates more tiles and exposes more
independent wavefront work, but reduces computation per tile and
increases dependency/scheduling frequency. Too many small tiles increase
overhead, as the 32- and 64-factor measurements demonstrate.

% ============================================================
\section{Conclusions}
% ============================================================

Among the retained Jacobi traces, the v3 pointer-alternation version
has the lowest 16-worker elapsed time (0.17 s), compared with 0.20 s
for v2 and 1.50 s for v1. The model's reported parallel fraction rises
from 73.83\% in v1 to 98.62\% in v2. For Gauss--Seidel, the explicit
task version reaches 3.78x speedup at 16 workers, while the initial
do-across trace reaches 8.43x; the v3 trace reports 18.24x, subject to
the \texttt{-u} value being equal to 8.
The best parameter in the retained 16-worker sweep is
\texttt{userparam}=8 at 0.421 s. At 16 workers, the do-across memory
trace also records about 40 times fewer L2 misses per worker than the
explicit-task trace, although different nodes and unknown completed
work prevent a causal comparison.
